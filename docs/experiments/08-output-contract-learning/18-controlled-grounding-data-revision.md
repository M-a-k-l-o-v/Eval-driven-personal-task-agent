# Controlled Training-Data Revision: Policy and Grounding Variation

**Status:** Owner built, validated, trained and evaluated; candidate not promoted.
Date: 2026-10-16.

## Hypothesis and Scope

The [training audit](17-training-target-coverage-and-state-grounding.md) found
correct but narrow state-grounding examples and a retained urgency-policy defect.
Prepare a separate data-quality experiment before considering more epochs.
This is a combined policy/wording/state intervention; an eventual result cannot
identify which of those components caused any change.

Only eligible BAYMAX rows inside the existing 1,000-row training cap change.
Preserve their positions and broad classes, all REFUSE targets, all xLAM rows,
the rest of the training file, and validation/test bytes. No resplitting, new
examples from held-out fixtures, oversampling, or new framework is introduced.

The reference is unweighted two-epoch QKVO name-first SFT, config hash
`684a76cd39d845b6177bdaee495bb77bcb436406d384baf912f80b8164fb8b8b`.
Its parent dataset revision is
`685a6b67832a5c55f54f2fc529f5c5234a05baa93d3e0cf241c38c006b9bbc12`.
The transform version is `training-grounding-v1`, not a claim that the whole
dataset was regenerated by generator 15 or 16.

## Previewed Changes

The model-free preview on the actual capped pool applies 49 changed rows:

| Generic rule | Rows | Change |
| --- | ---: | --- |
| Explicit deadline clarification | 3 | Bare "soon" requests become explicit "due soon" requests, so their CLARIFY target is appropriate. |
| Missing-fields wording | 4 | Rephrase calendar requests and questions while retaining both missing time and duration. |
| Undated-task ACT | 10 | Replace eligible dated task requests with explicit undated urgency requests; omit due_date without inventing one. |
| Entity-state variation | 27 | Preserve the uniquely named target, vary its internal ID and position, and add an unrelated entity. Calendar distractors use a different date to avoid inventing a scheduling conflict. |
| Clipboard-content binding | 5 | Vary instruction wording and clipboard values while binding the task title or email body to that state. Task cases also include an unrelated existing task. |

One additional undated-task candidate would duplicate an earlier revised input.
Its original dated parent is retained unchanged. The change journal records this
skip explicitly; provenance counts distinguish applied changes from skipped rows.

The urgency correction does not relabel the three CLARIFY rows into ACT, which
would change quotas. It revises their requests to genuinely require a deadline;
separate existing ACT slots teach the agreed undated behavior. This is a new
training artifact, not a rewrite of evaluation targets or old results.

Task/clipboard variants use independent stock/equipment text and generic phrasing,
not held-out scenario solutions. Unspecified draft subjects are omitted where
the subject is not required; supplied recipients and content remain grounded.

No claim of sophisticated semantic diversity is made: the bank remains small,
and structural row uniqueness is not a measure of conceptual independence.

## Preparation and Integrity

`scripts/prepare_sft_grounding.py` uses a focused training-only derivation in
`baymax.models.sft_grounding`. It rejects populated destinations, validates the
reference identity, copies its training settings into a newly hashed config,
and records source/output file hashes plus every changed row's before/after SFT
messages. Parent source identities and split membership remain unchanged; the
change report records transformed content rather than misrepresenting parent
row hashes as new-content hashes.

Changed targets pass the existing strict contract validator and in-memory fake
adapter/state validation. No live tool or external API executes. Full preparation
rejects revised inputs that duplicate training inputs or overlap any protected
validation/test input. It checks source counts, prompt hashes, source stability,
and exact held-out byte preservation before publishing from a staging directory.
Exact overlap checks do not prove semantic/template separation.

The preview validates the capped changes and counts only. It creates no dataset,
config, model or tokenizer and does not replace the full preparation checks.
Tiny fixture tests cover deterministic rules, grounded arguments, class/slot
preservation, unchanged held-outs, duplicate/overlap rejection, and no-overwrite
behavior. No full project build or training was run by the coding agent.
